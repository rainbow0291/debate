# 뉴스 쟁점 찬반 브리핑

논쟁적인 한국 경제/정책 뉴스를 짧고 중립적이며 출처가 명시된 찬반
브리핑으로 만든다. 이 스킬은 투자 조언이 아니며, 이슈에 대한 스킬 자신의
의견도 아니다 — 각 진영이 실제로 어떤 주장을 하고 있는지를 근거와 함께
보여주는 것이 목적이다.

## 1단계 — 이슈 찾기와 검증

사용자가 지목한 기사/주제를 가져오거나, "오늘 뉴스 중 쟁점 뽑아줘"처럼
막연히 요청받았다면 직접 최근 한국경제 기사를 수집한다. 이 플러그인은
`kr-econ-news-digest` 플러그인과 완전히 독립적이므로, 그 플러그인이
설치되어 있다고 가정하지 말고 한국경제 RSS를 직접 가져온다 (예: `economy`,
`politics`, `realestate`, `international` 피드,
`https://www.hankyung.com/feed/...`).

모든 기사가 논쟁거리는 아니다. 정책 변경, 규제안, 논란이 된 판결, 노사
갈등처럼 진짜 대립이 있는 이슈만 골라내고, 실적 발표나 단순 인사처럼
사실 보도성 기사는 제외한다. 사용자가 고른 주제가 사실 확인 결과 순수
사실 보도이고 딱히 "반대편"이 없다면, 그렇다고 솔직히 말하고 억지로
찬반 구도를 만드는 대신 그냥 일반 요약을 제안한다.

핵심 쟁점은 어느 쪽도 미리 옳다고 전제하지 않는 중립적인 한 줄 질문으로
표현한다. 예: "정부의 OO 규제 강화안, 시행해야 하는가?"

## 2단계 — 양쪽 논거를 독립적으로 구성

이 플러그인의 `agents/` 디렉터리에 정의된 서브에이전트 두 개
(`pro-advocate`, `con-advocate`)를 Agent 도구로 각각 실행한다. 둘 다
쟁점 질문만 전달받고, 서로의 결과를 보지 못한 상태에서 자신이 맡은
쪽의 가장 설득력 있고 정직하게 출처가 확인된 논거를 만들도록 지시한다
— 한쪽이 다른 쪽을 보고 논조를 누그러뜨리거나 따라가지 않도록 하기
위함이다.

**출처 균형이 중요하다.** 한국경제는 자체 논조가 시장·기업 친화적인
편이므로, 양쪽 논거를 전부 한국경제 기사만으로 구성하지 않는다. 각
에이전트가 어떻게 외부 출처(다른 매체, 공식 통계, 1차 자료)를 끌어와야
하는지는 `references/sourcing-guidelines.md`를 참고한다 — "반대" 측이
한 매체의 기업 친화적 프레이밍에서 나온 허수아비 주장이 되지 않도록
하기 위함이다.

## 3단계 — 중립적인 브리핑으로 종합

두 에이전트의 결과를 `references/output-format.md`에 정의된 구조로
합친다: 중립적인 쟁점 질문, 짧은 배경 설명, 출처가 달린 찬성 논거,
출처가 달린 반대 논거, 그리고 마지막 중립 고지문. 어느 한쪽을 실제
출처로 뒷받침할 수 없다면, 논거를 지어내는 대신 그 쪽에 **`확인 불가`**
라고 명시한다.

최종 확정 전에 초안을 파일로 저장한다 (파일명에 `issue-brief`가 들어가고
`.md`로 끝나는 경로 — 이 플러그인에 포함된 훅이 이 패턴에 맞는 파일을
저장할 때마다 출처 균형을 검사하고, 부실하면 저장을 막는다).

**국회 의안정보 선택적 활용**: 쟁점이 계류 중이거나 최근 발의된 법안과
관련이 있고, 이 계정에 (별도로 사용자가 직접 설치한) `assembly-api-mcp`
도구가 연결되어 있다면 — `ToolSearch`로 `mcp__assembly-api__assembly_bill`
같은 도구가 있는지 확인 — 이를 이용해 실제 의안 상태(제안일, 소관위,
처리 단계 등)를 가져와 중립적인 배경 사실로만 덧붙인다. 어느 쪽 논거로도
쓰지 않는다. 이 도구는 이 플러그인에 기본 포함되어 있지 않으며 (사용자
본인 명의의 open.assembly.go.kr API 키가 필요 — 자세한 설치 방법은
README 참고), **연결되어 있지 않으면 사용자에게 언급하거나 오류로
취급하지 말고 그냥 조용히 건너뛰고 나머지 절차를 평소대로 진행한다.**

## 4단계 — 전달

기본값: 브리핑을 채팅에 바로 보여준다.

사용자가 이메일이나 카카오톡으로도 받고 싶다고 하면, 새로 자격증명
처리 로직을 만들지 말고 이 계정에 이미 있는 발송 수단(news-digest류
플러그인의 `.env` 기반 SMTP 설정, 또는 PlayMCP 카카오톡 도구)을
재사용한다 — 무엇이 연결되어 있는지 `ToolSearch`/`ListConnectors`로
확인하고, 보내기 전에 목적지를 사용자에게 확인받는다. 비밀번호는
채팅에서 절대 묻거나 출력하지 않는다.

## 원칙

- 다루는 이슈 자체에 대해 스킬 자신의 의견을 말하지 않는다. 모든
  주장은 "찬성 측은 ~라고 주장한다" / "반대 측은 ~라고 본다" 식으로
  출처를 명시해 전달하며, 사실인 것처럼 단정하지 않는다.
- 모든 논거에는 실제로 확인 가능한 출처(기사, 공식 발표, 통계)가
  있어야 한다 — "균형을 맞추기 위해" 논거를 지어내지 않는다.
- 어느 쪽이 옳은지 판단해달라는 요청을 받으면 그 틀을 정중히 거절하고
  균형 잡힌 브리핑을 대신 제공한다 — 그건 독자가 스스로 내려야 할
  가치 판단이지, 이 스킬의 역할이 아니다.
